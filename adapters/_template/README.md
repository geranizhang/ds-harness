# Adapter template

Copy this directory to `adapters/<your-team>/`, fill in every file, then `export DS_HARNESS_ADAPTER=<your-team>`.
The core workflow runs without an adapter, but every platform-specific check degrades to "fill in your adapter".

| File | What goes in it | Who reads it |
|---|---|---|
| `adapter.json` | Regions, fetch limits, file naming, forbidden words, guard patterns, paths to the files below | every script, the hook, the agents |
| `checks.py` | SQL dialect and compliance rules as code (`sql_checks(sql, region) -> (errors, warnings)`) | `validate_sql.py`, the guard hook |
| `references/platform.md` | How to run a query on each region/engine: auth, queues, submit, poll, fetch, known truncation and gateway quirks | `data-runner` |
| `references/tables.md` | Table handbook. Keep the **scope index** at the top (global-replica vs partitioned-by-region); the runner checks it before summing across regions | `data-runner`, main session |
| `references/metrics.md` | Metric dictionary. Keep **rules** and **dated evidence** in separate blocks | both agents, main session |
| `references/glossary.md` | Team shorthand, default analysis scene, enumerations that must keep their canonical names | main session, `report-writer` |
| `references/delivery.md` | How your team publishes a report (docs tool, embedded tables, sheet write conventions) | main session (gate four) |
| `exemplars/` | 1–3 finished reports your team considers exemplary, plus a one-line note on what type each is. `report-writer` reads them before every outline | `report-writer` |
| `vocab.txt` | Team vocabulary whitelist. Top half is generated by `build_vocab.py` from the references and exemplars; bottom half (after `# --- manual ---`) is hand-maintained | `validate_doc.py` |
| `channel/` | Optional. A `metadata_assistant` script (ask your internal data catalog bot a factual question, print its reply) and anything the `qa-followup` channel needs | main session §2, `qa-followup` |
| `CHANGELOG.md` | When and why a rule in *this adapter* changed. Rule text itself carries no dates | maintainers |

## Conventions the core assumes

- `regions` are the independent data partitions you must query separately (data centers, shards, tenants). If you have one, list one.
- A raw file is `raw/YYYYMMDD_<content>_<REGION>.csv` + same-name `.sql` + same-name `.meta.json` with `rowCount` (engine side) and `fetched` (rows actually retrieved). Truncation = `fetched != rowCount`.
- The SQL header block (first `header_lines` lines) must contain every `header_markers` word: goal, metric definition, scope. Rename the markers to your language.
- Delivery tables carry one row per region plus one `aggregate_row_label` row; ratios are summed-then-divided, never averaged across regions.
